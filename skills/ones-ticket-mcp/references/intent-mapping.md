# 中文意图映射

仅在需要把自然语言转换为查询、详情或导出请求时读取。本文件不替代 MCP input schema。

## 先选择操作

按下列优先级归类：

1. 出现“下载到本地、导出、保存到本地、获取到本地”时，调用 `ticket_export`；即使句中也有“查看”或“获取”。
2. 出现“详情”且指向单张工单时，调用 `ticket_get`；纯数字号遵循查询契约中的解析步骤。
3. “查看、查阅、查询、列出、获取 ONES 工单”调用 `ticket_search`，只返回列表摘要。
4. 裸“获取”不表示本地写入；只有明确的本地目标才导出。

## 导出模式

- 同一请求包含“计划、预览、先看看、先查看导出范围、先给我计划”等预览词和本地导出目标时，调用 `ticket_export` 并显式传 `mode: "plan"`；只返回计划，不写入。
- 其他明确的“下载到本地、导出、保存到本地、获取到本地”请求就是写入授权，调用 `ticket_export` 并显式传 `mode: "write"`，不再要求用户重复确认。
- “先看看我的工单”但没有本地目标时仍是 `ticket_search`，不是导出计划。
- 用户后续说“按刚才计划导出”时，使用此前计划的完全相同 query、selection 与 media 调用 `mode: "write"`。

## 将范围和状态分别归一化

| 中文表达 | `scope` | `state` |
| --- | --- | --- |
| 获取 ONES 工单、获取我的待办、获取我未完成的工单 | `self` | `open` |
| 获取所有 ONES、获取 ONES 所有工单、获取我的全部工单 | `self` | `all` |
| 获取所有人的工单、获取全员工单 | `project` | `open` |
| 获取所有人的所有工单、获取整个项目全部工单 | `project` | `all` |
| 获取我正在处理的工单、我的活跃工单 | `self` | `active` |
| 获取我已完成的工单 | `self` | `done` |

- “所有人的、全员、整个项目、团队所有人”设为 `scope: "project"`；其他范围（包括未说明）使用 `self`。
- “待办、未完成、未关闭”设为 `open`；“正在处理、活跃”设为 `active`；“已完成”设为 `done`；“所有工单、全部状态、包含已完成”设为 `all`。
- 更具体的状态词优先于“所有”；“所有未完成工单”仍是 `open`。
- “所有”修饰人时只改变范围，修饰工单或状态时才表示 `state: "all"`。

## 不要误解人员语义

`scope: "self"` 代表当前用户是负责人。用户说“我创建的”或“我提交的”时，不要当作负责人条件；当前 schema 无法表达时，说明这一差异或请用户澄清。
