# OnES 工单采集 MCP：研究与方案建议

## 结论

不要复制或绕过付费 MCP，也不要规避登录、验证码、MFA 或访问控制。首期优先采用租户已授权的 API/导出能力；在租户明确允许、且存在独立只读机器凭据时，可以额外启用一个**受限的内部 GraphQL 读取适配器**。它不是 ONES 官方 API，也不是通用承诺；浏览器会话读取只能作为日后经单独批准的本地桥接能力。

OnES 官网将 ONES Project（项目管理）和 ONES Desk（工单管理）列为不同产品；实施前必须确认目标是研发工作项还是服务台工单。来源：[ONES 官网](https://ones.cn)。

## 建议架构

```text
MCP tools
  └─ OnES connector (API | browser session | file import)
       └─ Canonical ticket normalizer
            └─ Local writer + manifest + optional attachment downloader
```

### 连接器

| 优先级 | 方式 | 适用条件 | 取舍 |
| --- | --- | --- | --- |
| 1 | 已授权 API 或导出 | 租户允许令牌/API/导出 | 最稳定、最快、最易增量同步 |
| 2（租户特定） | 已授权内部 GraphQL 契约 | 管理员允许固定只读端点，且有非浏览器的只读机器凭据 | 网络效率高、LLM token 为 0；但契约易变，必须隔离实现并设停止条件 |
| 3 | CSV/HTML/Markdown 导入 | 不能自动读取或需要先验证字段模型 | 最合规、无需保存登录态，但非实时 |
| 延后 | 用户授权的本地浏览器桥接 | 租户书面允许且有独立的浏览器安全设计 | 页面变动风险高，不纳入首期 |

如果未来批准浏览器桥接，它只能读取用户在浏览器中已获授权访问的页面；遇到登录、MFA、验证码、403/429 或挑战页立即停止并返回“需要用户操作/权限不足”，不尝试规避。

## MCP 工具边界

第一版建议只实现下列低风险工具：

| 工具 | 输入 | 输出 |
| --- | --- | --- |
| `ticket_connection_status` | `profile` | 连接方式、授权状态、可用范围；不返回密钥 |
| `ticket_get` | 工单键或 URL、字段范围 | 精简工单对象和内容摘要 |
| `ticket_export` | 工单键或 URL、落盘 profile、是否含附件 | 导出清单、文件路径、内容哈希、警告 |

`ones_export_status`、`ones_ticket_search`、批量导出、评论/附件全量下载放到第二版，避免一开始形成高频拉取。

密码、OTP、Cookie、访问令牌、验证码答案和落盘根目录均不应是工具参数或工具输出。目录由服务器启动配置固定；密钥由受控的本机密钥来源解析。

## 凭据与登录

1. **首选：短期访问令牌或服务账号**。由租户管理员创建最小只读权限的凭据，运行 MCP 时通过环境变量或操作系统密钥库注入。
2. **手动导入：安全回退**。用户从 OnES 正常导出文件，由 MCP 在本地规范化；不需要保存登录态。
3. **浏览器会话：后续独立能力**。需要单独的本地桥接、用户授权和租户许可，不采集密码或导出 Cookie。
4. **不支持：工具参数中传账号密码**。这会把秘密暴露给调用记录、模型上下文和日志，也不兼容 MFA/验证码。

`mcpServers` 配置可以声明命令、非秘密 profile 和环境变量名，但不应直接写账号、密码、Cookie 或 Bearer token。首版只接受管理员签发/批准的只读机器令牌；若内部 GraphQL 只能通过复制浏览器 Cookie 工作，则只可作为人工短期调试证据，不能作为无人值守 MCP 认证方案。

应定义 `SecretProvider` 接口，首版实现环境变量和 Windows 凭据管理器。配置文件只保留 `baseUrl`、连接器类型、允许项目范围和密钥引用名，不保存秘密值。

## 合规与反自动化

- 先取得租户管理员对读取和本地保存范围的明确授权，并核验 OnES 合同、租户策略和数据保留要求。
- 只读取调用者本来可见的内容；不枚举项目、不探测隐藏接口、不解析或复用浏览器 Cookie。
- 默认单并发、按需读取、基于内容哈希缓存、指数退避处理 429/5xx；限速由管理员配置，不能写死或试探阈值。
- CAPTCHA、MFA、访问挑战或权限不足是停止条件，而不是需要绕过的技术障碍。

### 已捕获的列表查询：能力与边界

已审阅的 GraphQL 请求是树形列表索引，而非完整工单读取。它返回 `buckets[0].tasks` 中的 `uuid`、`parent.uuid`、`path`、状态、子项计数、工作项类型标识和 `importantField`；因此能确定父子关系、状态和列表展示字段。它的当前筛选排除了已完成项，并限制为“当前用户负责”的工作项，不能直接用作全量同步查询。

该查询没有请求描述、评论或附件；这些必须由经验证的详情/评论/附件读取契约按单工单按需获取。响应中还携带租户布局/字段配置数据，可用于将稳定 `fieldUUID` 映射为“负责人、类型、优先级”等 profile 配置；绝不把字段显示名或页面 DOM 当成跨租户契约。捕获文件不是合格 fixture：需先保留为 UTF-8、可解析的脱敏 JSON，且不得进入仓库。

## 标准化和落盘

建议每张工单单独落盘：

```text
<exportRoot>/ones/<project>/<ticket-key>/
  ticket.md        # 面向阅读的规范化内容
  ticket.json      # 标准化结构化数据
  comments.json    # 脱敏后的富文本评论结构及作者/时间
  relations.json   # 父、子及关联工作项
  attachments/manifest.json # 附件元数据；二进制下载需显式开启
  source.json      # 可选：最小化原始响应/导入记录
  manifest.json    # 来源 URL、读取时间、内容哈希、版本、附件清单
```

分类使用租户配置的显式映射（如工作项类型、标签、字段值 → `bugfix` / `feature` / `technical-change`），而不是先用 LLM 猜测。`manifest.json` 应保留采集方式、时间、源标识和哈希，支持幂等导出与变更追踪。

## 速度与 token 成本

- 采集、字段映射、Markdown 渲染和哈希均应是确定性代码，正常同步的 LLM token 成本为 **0**。
- 只把“生成摘要/实施建议”作为显式可选步骤；输入仅使用标题、描述、验收标准和必要评论，并按 `contentHash + promptVersion` 缓存结果。
- 固定 GraphQL 查询与已授权 API 都比浏览器读取更快、更稳定；首期不实现浏览器连接器或抓包功能。
- 列表读取必须分页并仅保留索引字段；用户选择一张工作项后再读取详情、评论和附件元数据，避免把整棵树和富文本正文送入 MCP 上下文。
- MCP 工具输出默认返回摘要、分页信息和产物路径，而不是整批正文；这样能控制调用方上下文和 token 消耗。

## 实施前需要确认

1. 目标产品是 ONES Project 工作项还是 ONES Desk 服务台工单？请提供一条已脱敏的工单 URL 或字段截图即可。
2. 租户是否允许只读 API、导出，或受限内部 GraphQL 契约？由谁提供最小权限的只读机器令牌？
3. 本地落盘规范：根目录、是否保留评论/附件、保留期限、敏感字段脱敏规则。
4. 首期范围是单工单按 URL 导出，还是按筛选条件批量同步？
